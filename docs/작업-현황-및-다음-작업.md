## 2. 다음 작업 — 원격 제어

### 2-1. 무엇을 만드나

실습 시험 중 학생이 의도하지 않은 조작으로 프로그램이 죽거나 오류가 나면, 교수가 화면 크게 보기(`DetailMonitoring`)에서 바로 그 학생 PC 를 원격으로 조작해 해결한다.

- **1 대 1** — 교수 한 명이 한 번에 학생 한 명만 조작한다. 다른 학생과 원격 중이면 버튼이 잠긴다.
- **C# 으로 만든다.** 쓸 수 있는 라이브러리가 있으면 그것을 먼저 쓴다.
- 들어갈 자리: 교수 `DetailMonitoring` 창에 [원격 제어] 버튼, 학생 쪽은 학생 프로그램 안.

### 2-2. 지금 화면 모니터링은 이렇게 돈다

```
학생 ScreenCaptureService ──2초마다 JPEG 1280×720 (품질 80)──▶ PacketType.ScreenCapture (70)
   ──▶ 교수 App.xaml.cs ──▶ ScreenBoardViewModel ──▶ StudentScreenViewModel ──▶ ScreenMonitoring / DetailMonitoring
```

- 보기만 한다. 교수 쪽에서 학생 PC 로 입력을 보내는 경로는 아직 없다.
- 캡처는 주 모니터만, GDI(`BitBlt`)로 찍고 WPF `JpegBitmapEncoder` 로 줄인다. 외부 패키지는 없다.
- 네이티브 통신 DLL 은 파일 전송 패킷만 직접 처리하고 나머지 종류는 C# 으로 넘긴다. 그래서 원격 제어용 패킷 종류를 새로 넣어도 **DLL 을 다시 빌드하지 않아도 될 가능성이 높다** (`ClientSession.cpp`, `StudentClient.cpp` 에서 확인할 것).

### 2-3. 꼭 지켜야 할 제약

1. **방화벽 방향** — 시험 중 학생 PC 는 방화벽이 모든 프로필에서 켜지고, 교수 PC 를 뺀 바깥 통신이 막힌다(`FirewallPolicyService`). 들어오는 연결은 Windows 기본값(차단)이다.
   → **학생 PC 가 교수 PC 로 접속하는 방향**이어야 추가 규칙 없이 통한다. 교수 PC 가 학생 PC 로 접속하는 방식이면 학생 PC 에 인바운드 허용 규칙을 따로 넣어야 한다.
2. **감시·금지 목록과 부딪히지 않기** — 원격 도구(`mstsc` 등)는 금지 목록 후보에 있다(`Shared/KnownPrograms.cs`). 학생 PC 에서 별도 실행 파일(VNC 서버, AnyDesk 등)을 띄우면 감시에 걸린다.
   → 원격 받는 쪽은 **학생 프로그램 프로세스 안에서** 돌아야 한다.
3. **학생 프로그램 자체가 죽은 경우** — 원격 받는 쪽이 학생 프로그램 안에 있으면, 학생 프로그램이 죽었을 때는 원격도 못 한다. "죽는 프로그램"이 실습용 프로그램(VS 등)인지 우리 학생 프로그램인지에 따라 설계가 달라진다(2-7 참고).
4. **권한** — 학생 프로그램은 방화벽을 바꾸므로 관리자 권한으로 돈다. 그래서 관리자 권한 창에도 입력을 보낼 수 있다. 다만 UAC 확인 창·Ctrl+Alt+Del 같은 보안 데스크톱은 어떤 방식으로도 조작할 수 없다.
5. **시험 공정성** — 원격 중 입력은 교수 것인지 학생 것인지 구분되지 않는다. 시작·종료 시각을 시험 로그에 남기고, 학생 화면에 "교수님이 원격으로 조작 중" 표시를 띄운다.
6. **대역폭** — 원격은 한 명에게만 걸리므로, 그 학생만 화질·주기를 올리면 된다. 나머지 학생의 2초 캡처는 그대로 둔다.

### 2-4. 후보 방식

> 아래 라이브러리 설명은 작성 시점에 웹 검색을 쓰지 못해 기억에 의존했다. **구현 전에 문서·지원 에디션·유지보수 상태를 다시 확인할 것.**

| | A. Windows Desktop Sharing API | B. 기존 통신 확장 + 입력 주입 | C. VNC 라이브러리 |
|---|---|---|---|
| 무엇 | Windows 에 들어 있는 화면 공유 COM(`rdpencom.dll`, `RDPCOMAPILib`). 학생은 `RDPSession`(공유하는 쪽), 교수는 `RDPViewer` ActiveX(보는 쪽) | 원격 중인 학생만 캡처 주기를 올리고, 교수 창의 마우스·키보드를 패킷으로 보내 학생 PC 에서 `SendInput` 으로 재현 (입력 재현 라이브러리 예: `H.InputSimulator`) | 학생 프로그램 안에 VNC 서버, 교수 프로그램에 VNC 클라이언트 (예: `RemoteViewing`) |
| 설치 | 없음 (Windows 기본) | NuGet 하나 정도 | NuGet |
| 화면·입력 처리 | Windows 가 다 한다 (RDP 압축, 변경 영역만 전송, 조작 권한 단계) | 직접 만든다 (화질·지연 튜닝) | 라이브러리가 한다 |
| 연결 방향 | **역방향 연결 지원** — 교수가 대기하고 학생이 접속 가능 → 방화벽 제약과 맞음 | 이미 붙어 있는 교수↔학생 연결을 그대로 씀 → 방화벽 문제 없음 | 보통 교수가 학생 PC(5900 포트)로 접속 → 학생 PC 인바운드 규칙 필요 |
| 학생 PC 에 따로 뜨는 실행 파일 | 없음 (학생 프로그램 안) | 없음 | 없음 |
| 어려운 점 | COM·ActiveX 연동(WPF 에 `WindowsFormsHost` 로 넣기), 자료가 적음, 연결 문자열을 기존 통신으로 넘겨야 함, 교수 PC 에 대기 포트 인바운드 허용 필요 | 화질·끊김을 직접 다뤄야 함, 키 조합·좌표 변환(DPI·다중 모니터) 직접 처리 | 방화벽 방향이 반대, 라이브러리 유지보수 상태 확인 필요, WPF 표시 직접 구현 |

외부 제품(AnyDesk · TeamViewer · RustDesk)은 금지 목록·감시·인터넷 차단과 부딪히고 C# 으로 붙일 수 없어 제외한다.

**추천: A 로 먼저 시험해 보고, 안 되면 B.**
- "라이브러리 우선" 원칙에 가장 맞는다. 화면 전송과 입력 처리를 Windows 가 맡는다.
- 역방향 연결을 쓰면 학생 PC 방화벽 규칙을 건드리지 않아도 된다.
- B 는 외부 의존이 가장 적고 이미 검증된 통신을 쓰므로 안전한 대안이다. A 의 PoC 가 막히면 바로 B 로 간다.

### 2-5. 흐름 (A 기준 초안)

```
교수 DetailMonitoring [원격 제어]
  → 확인 창 ("김OO 학생 PC 를 원격으로 조작합니다")
  → 교수 PC: RDPViewer 가 역방향 대기, 연결 정보 생성
  → 교수 → 학생: RemoteControlStart 패킷 (연결 정보)
학생 프로그램
  → RDPSession 열고 교수 PC 로 접속
  → 화면 맨 위에 "교수님이 원격으로 조작 중" 띠 (닫을 수 없음)
  → 감시 모듈에 원격 중임을 알림 (원격 세션을 부정행위로 잡지 않게)
교수
  → 보기 → [조작 권한 켜기] → 문제 해결
  → [원격 종료] → RemoteControlStop 패킷, 양쪽 정리, 시험 로그에 시작·종료 시각 기록
끊김: 학생이 접속을 잃거나 교수 창을 닫으면 원격도 자동으로 끝난다.
```

새 패킷은 화면 모니터링 번호대(70~79)에 둔다. 예: `RemoteControlStart = 71`, `RemoteControlStop = 72`, `RemoteControlState = 73`(학생 → 교수, 접속됨·실패 이유).

### 2-6. 작업 순서

1. **PoC (가장 먼저)** — PC 두 대로 A 방식 역방향 연결을 붙여 본다. **학생 PC 에 시험용 방화벽 차단을 건 상태에서** 되는지, 강의실 PC 의 Windows 에디션에서 되는지 확인한다. 안 되면 B 로 PoC.
2. 통신 형식 — `Protocol.h` · `NetworkInterop.cs` 에 패킷 추가, 페이로드 구조 정의.
3. 교수 — `RemoteControlService`(세션 하나만 허용, 시작·종료·상태), `DetailMonitoring` 에 버튼과 원격 화면 영역.
4. 학생 — `RemoteControlService`(요청 받기, 세션 열기·닫기), 원격 중 표시 띠.
5. 감시·로그 연동 — 원격 중 감시 오탐 막기, 시험 로그·경고 목록에 기록.
6. 실기 테스트 — 강의실 PC 로 끊김·재접속·시험 종료 중 원격 등 예외 상황 확인.

### 2-7. 시작 전에 정할 것

1. **"죽는 프로그램"이 무엇인가** — 실습용 프로그램(VS, 편집기)이 멈추는 경우만인가, 우리 학생 프로그램이 죽는 경우도 포함인가? 후자면 학생 프로그램 밖에서 도는 작은 도우미 프로세스가 필요하다(지금 `FirewallGuard` 가 같은 실행 파일을 다른 인자로 띄우는 방식이라 참고할 수 있다).
2. **학생 동의** — 교수가 바로 조작하는가, 학생 화면에 [허용] 버튼을 띄우는가?
3. **원격 중 시험 처리** — 남은 시간을 멈추는가? 원격 중 감시(금지 프로그램 종료 등)를 잠시 끄는가?
4. **강의실 PC 환경** — Windows 에디션, 모니터 수, 화면 배율(DPI).
5. **원격 기록** — 시험 로그 엑셀에 원격 이력 칸을 추가하는가?
