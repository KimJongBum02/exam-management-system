# 문서 3/3 — 유저플로우 (스윔레인 5개, 확대 캡처 5장 연결)

노드 표기: [화면] = 사각(보라) / <데이터·목록> = 평행사변형(파랑) / {분기} = 마름모(주황) / (액션) = 둥근사각

## 레인 1. 프로그램 진입 및 연결
- ●앱 최초 실행 → [프로그램 시작 화면] → {초기 연결 완료?}
  - N → [연결 오류 안내 화면] → (되돌아감) [프로그램 시작 화면]
  - Y → 레인 2 [메인 대시보드 화면]

## 레인 2. 메인 대시보드
- [메인 대시보드 화면] → <실시간 학생 상태 목록> → {예외 학생 존재?}
  - Y → [예외 학생 상세 화면]
  - N/이후 → "시험 시작 마법사 실행" 라벨을 타고 레인 3으로 하강
- 예외 학생 상세 화면에서도 붉은 경로로 레인 3(마법사 1단계)로 연결

## 레인 3. 시험 준비 마법사
- [마법사 1단계: 대기] → <접속 학생 현황> → {대기 단계 완료?}
  - N → (붉은 역방향) [마법사 1단계: 대기]로 복귀
  - Y → [마법사 2단계: 준비]
- [마법사 2단계: 준비] → (라벨 "시험 파일 선택" 경로) → <허용·금지 프로세스 목록> → (라벨 "프로세스 목록 …") → {준비 단계 완료?}
  - N → (붉은 역방향) [마법사 2단계: 준비]로 복귀
  - Y → [마법사 3단계: 파일배포]
- [마법사 3단계: 파일배포] → (라벨 "파일 일괄 배포 실행") → <학생별 다운로드 상태> → {배포 실패 학생 존재?}
  - Y → (라벨 "파일 재배포 실행") → [마법사 3단계: 파일배포]로 복귀 = 재배포 루프
  - N → {배포 단계 완료?}
    - N → (붉은 역방향) [마법사 3단계: 파일배포]로 복귀
    - Y → [마법사 4단계: 시험시작]
- [마법사 4단계: 시험시작] → (라벨 "시험 시작 실행") → 레인 4 [시험 관리 창]

## 레인 4. 시험 진행 관리
[시험 관리 창]에서 4갈래 분기:
1) → <부정행위 알림 목록> → {부정행위 알림 수신?}
   - Y → [부정행위 알림 상세] → (되돌아감) [시험 관리 창]
   - N → 계속 대기
2) → <진행 중 학생 상태> → {지각/재접속 학생?}
   - Y → (라벨 "파일 재배포 실행(관리창)") → [시험 관리 창]으로 복귀 = 관리창 내 재배포 루프
   - N → (붉은 경로, 라벨 "시험 종료 실행") → 레인 5 [시험 종료 및 답안수집]
3) → <학생 채팅 메시지> → (라벨 "채팅 메시지 전송") → [시험 관리 창]으로 복귀
4) → [보안 정책 관리 화면] → <허용·금지 프로세스 현황> → (라벨 "프로세스 목록 수정/삭제") → [보안 정책 관리 화면]으로 복귀

## 레인 5. 시험 종료 및 정산
- [시험 종료 및 답안수집] → <학생별 답안 수집 상태> → (라벨 "답안 일괄") → {답안 수집 완료?}
  - N → (붉은 역방향) [시험 종료 및 답안수집]으로 복귀 = 재수집 루프
  - Y → (흔적 삭제 승인) → (학생 PC 종료 승인) → [종료 완료 현황 화면] → <종료·정리 완료 상태> ●끝

## 구조적 특징 (설계 시 반영할 것)
- 되돌아오는 루프가 총 6개: 연결 재시도 / 대기 단계 / 준비 단계 / 배포 단계(2개: 재배포 + 단계완료) / 답안 재수집
- 마법사 각 단계는 "완료?" 게이트를 통과해야 다음으로 진행 (선행 단계 미완료 시 진행 불가 규칙과 일치)
- 파일 재배포 진입점이 2곳: 마법사 3단계(배포 실패 학생) + 시험 관리 창(지각/재접속 학생)
- 시험 관리 창은 허브 구조 — 4개 서브 화면/목록이 모두 관리 창으로 복귀
- 종료 이후는 되돌릴 수 없는 단방향(흔적 삭제 → PC 종료 → 완료 현황)

# 【개정】 2026-09-04 사용자 확정 흐름 — 위 초안의 준비 단계 순서를 대체함

초안은 "학생 접속 대기 → 준비(파일·정책) → 배포 → 시작" 이었으나,
파일·정책·서버가 학생 접속보다 앞서도록 뒤집혔다.

1. 교수가 파일을 올리고 압축·암호화하여 배포 준비를 끝낸다
2. 금지/허용할 프로세스를 지정한다
3. 서버를 연다
4. 학생이 접속한다
5. 접속한 학생의 상태가 모두 파악되면 다음 단계로 진행할 수 있다
6. 모든 준비가 완료되면 시험을 시작한다
7. 시험 관리 화면에서 시험 전반을 관할한다
8. (예외) 학생이 시험을 미리 끝내고 답안을 제출할 수 있다.
   → 교수쪽 종료 버튼과 학생쪽 종료 버튼이 각각 필요.
   → 지금은 교수 UI만 수정하므로 교수쪽만 작업한다.
9. 조기 제출 학생 + 교수가 종료시킨 학생의 답안을 수집한다
10. 수집이 끝난 학생 자리의 배포 파일 경로를 모두 지우고 PC를 종료한다
11. 모든 과정이 끝나면 다시 처음 화면으로 돌아간다

## 확정된 마법사 4단계 (사용자 선택: 4단계 재배치)
- 1단계 시험 준비 : 파일 업로드 + 암호화·압축 + 허용/금지 프로세스 지정  (1·2번)
- 2단계 학생 접속 : 서버 열기 + 접속 현황 + 전원 상태 파악              (3·4·5번)
- 3단계 파일 배포 : 일괄 배포 + 실패 학생 재배포
- 4단계 시험 시작 : 압축 해제 요청 + 진행 중 전환                       (6번)

## 초안 대비 달라지는 점
- 마법사 1단계가 "대기"에서 "시험 준비"로 바뀜 (학생 접속은 2단계로 밀림)
- "서버 열기"를 한때 교수의 명시적 조작으로 올렸으나 2026-09-09 에 되돌렸다.
  수업 중 OX 퀴즈·화면 모니터링만 쓰는 경우에도 마법사를 거쳐야 해서다.
  지금은 초안대로 App 이 뜰 때 바로 열리고, 2단계는 접속 현황을 보는 자리다.
- 학생 조기 제출이라는 상태가 새로 생김 → 시험 중에도 "제출 완료" 학생이 존재
- 종료 완료 후 처음 화면으로 복귀하는 경로가 필요 (11번)
