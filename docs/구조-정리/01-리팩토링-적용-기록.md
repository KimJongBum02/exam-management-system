## 0. 작업 순서

1. 죽은 코드 삭제 (`_Legacy` 폴더, 옛 UI만 참조하던 파일, DNS 방식 코드)
2. **기능을 ViewModel → Service 로 이동** (파일 → 시험 흐름 → 채팅·보고 순)
3. 자리 정리 — 폴더·네임스페이스 정돈, 한 파일에 여러 클래스 나누기
4. Model 정리 (도메인별 묶음, UI 타입 제거)
5. 화면(View) 이름 변경
6. ViewModel·Service 이름 변경, 폴더 분류

**이름 변경(5·6)은 반드시 마지막에 한다.** 파일이 통째로 움직여 거의 모든 줄이 충돌로 잡히기 때문에, 팀원 작업과 겹칠 가능성이 있으면 기능 이동(2)을 먼저 올리는 편이 안전하다.
단계마다 빌드했고, 2번부터는 실행해서 확인했다.

- 목록 한 줄짜리도 `…ViewModel` 로 끝낸다. `Item` 접미사는 뜻이 모호해져 쓰지 않는다.
- `ViewModelBase` 의 옛 이름 `RightPanel…` 은 지금 없는 옛 오른쪽 패널의 흔적이었다.
- **`ViewModelBase` 라는 이름은 이제 저장소에 없다.** 뷰모델만 쓰는 것이 아니어서(Model · Service ·
  코드비하인드도 같은 바탕이 필요하다) 층 이름을 빼고 `Shared\UiBinding` 으로 옮겼다. 10장 참고.

### 합친 두 가지

**① `StudentItem` → `StudentStatusViewModel`**
배포 표 한 줄과 현황판 학생이 같은 학생을 두 벌로 들고 있었다. 합치면서 동기화 코드 약 40줄(`CreateRow`, `OnStoreStudentsChanged`, 이름 변경 구독)이 사라졌다.
- 배포 표는 `StudentStore.Instance.Students`를 그대로 쓴다.
- 배포용 값을 학생 뷰모델에 추가: `IsDeployTarget`, `DeployStatus`, `DeployProgress`, `DeployProgressText`, `SendingSessionId`
- **체크 상자는 반드시 따로 둔다.** 배포 표는 `IsDeployTarget`, 승인 표는 기존 `IsSelected`. 하나로 합치면 배포 때 전체 선택한 것이 승인 대상까지 바꿔 놓는다.
- [새 시험 준비]에서 배포 상태도 초기화한다(그러지 않으면 다음 시험 준비 화면에 지난 시험의 "수신완료"가 남는다).

**② `AnswerCollectViewModel` → `ExamEndViewModel` 로 흡수**
팀원이 [시험 종료]와 [답안 일괄 수집]을 **한 버튼**으로 합쳐 두었고, 승인까지 같은 화면(`ExamEndWindow`)에서 이어진다. 두 뷰모델이 똑같이 갖고 있던 `IsContainerEnabled`가 하나로 줄었고, `UiContext` 속성도 `ExamEnd` 하나가 되었다.

### 합치면 안 되는 것
`ChatViewModel`과 `ChatTabViewModel`은 1 대 N 관계다. 목록 한 줄마다 자기 객체가 있어야 줄마다 다른 값(미읽음, 마지막 메시지)을 보여 줄 수 있다. 합치면 대화 목록의 정렬·필터가 불가능해진다. 같은 이유로 `NoticeViewModel`, `StudentScreenViewModel`도 그대로 둔다.

### 서비스가 지키는 것
- **창을 띄우지 않는다.** 실패는 예외 대신 결과값(`PackageResult`, `SendResult`, `SendProblem`)으로 돌려주고, 확인·결과 창은 뷰모델이 띄운다.
- 실패 이유는 문자열 비교가 아니라 **열거형**으로 돌려준다(화면이 표 문구를 고를 때 쓴다).
- 네이티브 스레드에서 올라온 이벤트는 그대로 흘려보내고, 화면 스레드로 넘기는 것(`Dispatcher.BeginInvoke`)은 뷰모델이 한다.

## 5. Model 정리

```
Model/
├ QuizData.cs      QuizQuestion, QuizSubmission, QuizQuestionStat, QuizRound, QuizStudentTally  (9/28, 수업 확인 퀴즈)
├ SurveyData.cs    SurveyRound, SurveyResponse, SurveyStudentTally                         (9/28, 옛 QuizData)
├ AlertData.cs     AlertItem, AlertKind
├ ChatData.cs      ChatMessageModel
└ ProgramData.cs   ProgramEntry, ProgramSource
```

- 서비스 파일에 섞여 있던 데이터 클래스를 떼어냈다(`AlertStore.cs`, `QuizService.cs`, `ProgramPickerService.cs`).
- **Model 에서 WPF 타입을 없앴다.** `ProgramEntry.Icon`(`ImageSource`)을 지우고, 아이콘은 `Converter/FileIconConverter.cs`가 실행 파일 경로로 그린다. 덤으로 선택창이 목록을 만들 때 아이콘을 전부 뽑지 않아 더 빨리 뜬다.
- `MenuEntry`는 화면 상태(잠김·툴팁)라 ViewModel 로 옮겼다. `StudentModel`은 쓰이지 않아 지웠다.
- **남은 예외:** Model 의 일부 클래스는 여전히 `INotifyPropertyChanged`와 표시 문구(`StateText`, `AnswerText`, `ScoreText`, `Guide` 등)를 갖고 있다. 엄격히 하려면 화면별 래퍼 뷰모델이 필요해서, 이번에는 두기로 했다.

## 6. 함께 고친 버그

- **회차 번호가 빈 번호를 쓰지 않던 문제** — 아직 배포하지 않은 묶음이 있으면 그 번호를 그대로 재사용해서, 폴더에서 `T1`을 지워도 계속 `T2`가 만들어졌다. 지금 규칙: **폴더에서 비어 있는 가장 작은 번호**를 쓰고, 아직 배포하지 않은 내 묶음은 자기 번호를 비운 것으로 친다. 번호가 옮겨 가면 배포한 적 없는 옛 파일은 지운다. (`ExamReadyService.ChooseOutputPath`)

---

## 9. 퀴즈 개편에 따른 이름 변경 (2026-09-28)

OX 퀴즈 하나였던 기능을 **수업 확인 퀴즈**(OX·N지선다를 섞은 여러 문제, 채점, 퀴즈마다 엑셀 저장)와 **설문**(정답 없는 OX 한 문제, 파일 저장 없음) 둘로 나눴다.
이름 규칙: **수업 확인 퀴즈 = `Quiz…`, 설문 = `Survey…`.** 교수 쪽에만 적용했다.

| 역할 | 9/21 이름 | 9/28 이름 |
|---|---|---|
| 메뉴 6번 (두 탭을 나누는 화면) | `QuizWindow` | **`QuizTab`** |
| 수업 확인 퀴즈 탭 | — (새로 만듦) | **`QuizWindow`** |
| 설문 탭 | `QuizWindow` | **`SurveyWindow`** |
| 수업 확인 퀴즈 서비스 | — (새로 만듦) | **`QuizService`** |
| 설문 서비스 | `QuizService` | **`SurveyService`** |
| 수업 확인 퀴즈 작성 칸 | — (새로 만듦) | **`QuizViewModel`** (`UiContext.Quiz`) |
| 설문 작성 칸 | `QuizViewModel` (`UiContext.Quiz`) | **`SurveyViewModel`** (`UiContext.Survey`) |
| 수업 확인 퀴즈 데이터 | — (새로 만듦) | **`QuizData.cs`** |
| 설문 데이터 | `QuizData.cs` (`QuizRound` …) | **`SurveyData.cs`** (`SurveyRound` …) |

- **같은 이름이 역할을 바꿨다.** `QuizWindow`, `QuizService`, `QuizViewModel`, `QuizData.cs` 는 9/21 에는 OX 퀴즈(지금의 설문)였고, 지금은 수업 확인 퀴즈다. git 에는 이 파일들이 "내용이 통째로 바뀐 수정"으로 보인다.
- **서비스·데이터를 하나로 합치지 않은 이유:** 겹치는 것은 응답 구독·접속 학생 고르기 같은 뼈대 20~30줄뿐이고, 데이터 모양(O/X 하나 ↔ 문제별 답 목록)·채점·저장 방식이 모두 다르다. 합치면 한 클래스 안에 "설문이면 / 퀴즈면" 분기만 늘어난다.
- 함께 지운 것: 설문 엑셀 저장, OX 퀴즈 정답·채점 코드, 쓰이지 않던 `UiContext.QuizSession`, `PacketType.QuizResult`·`QuizResultPayload`, `QuizQuestionType.ShortAnswer`·`MultipleChoice`.
  - 참고: 학생에게 채점 결과를 보여 주는 기능을 만들게 되면 **`QuizResult` 라는 이름은 비어 있다.**

## 10. `Shared` 이전 뒤 달라진 것 (2026-10, PR #97 ~ #106)

교수 쪽만 정리하던 이 문서의 전제가 한 번 바뀌었다. **두 앱이 같이 쓰는 코드를
`ExamManager\Shared\` 한 곳으로 모았고**, 그래서 1 · 3장에 적힌 것 일부가 교수 폴더에서 빠져나갔다.

지금 `Shared\` 에 있는 것:
`FileSystem` · `FontSizes.xaml` · `HeaderBarPanel` · `KnownPrograms` · `StartMenuPrograms` ·
`UiBinding` · `UiCommand` · `UiFont` · `UiSignal` · `UiThread` · `UiWindow` · `CrashLog`

| 옮긴 것 | 어디서 | PR |
|---|---|---|
| `RelayCommand` → **`UiCommand`** | 교수 · 학생에 중복이던 두 벌을 한 벌로 | #100 |
| `ViewModelBase` → **`UiBinding`** | `ProfessorUI/ViewModel/Shell/` | #104 · #106 |
| 파일 처리 → **`FileSystem`** | 흩어져 있던 폴더 삭제 · 압축 · 암호화 | #99 |

**이름 규칙은 그대로다.** `…Service` · `…Store` · `…State` · `…Native`(4장 표)는 교수 폴더 안에서 계속 쓴다.
`Shared\` 로 올라간 것은 층 이름을 빼고 `Ui…` 로 시작하게 했다 — 뷰모델만 쓰는 것이 아니라
Model · Service · 코드비하인드도 같은 바탕을 쓰기 때문이다.

### 교수 쪽에서 그 뒤 더 바뀐 것 (PR #121 ~ #130)
